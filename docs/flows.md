# 기능 흐름도 (Flows)

> 주요 기능의 동작 흐름을 mermaid로 도식화한다.
> 설계 근거는 [`design.md`](./design.md), 화면은 [`ui.md`](./ui.md), 결정 로그는 [`tradeoffs.md`](./tradeoffs.md).

---

## 1. 앱 실행 → 잠금 해제

```mermaid
flowchart TD
    A([앱 실행]) --> B{이미 실행 중?}
    B -- 예 --> B1[기존 창 활성화] --> Z([종료])
    B -- 아니오 --> C{vault.dat 존재?}
    C -- 아니오 --> D[최초 설정 마법사 S2]
    C -- 예 --> E[잠금 화면 S1]
    E --> F[마스터 비밀번호 입력]
    F --> G[KDF: 비번+salt → 마스터키 KEK]
    G --> H{Wrapped DEK master 언래핑}
    H -- 실패 --> H1[비밀번호 오류 안내] --> E
    H -- 성공 --> I{본문 복호화 · 태그 검증}
    I -- 실패 --> I1[파일 손상 → bak 복구 안내 S9]
    I -- 성공 --> J[메인 화면 S3]
    J -. 유휴/최소화 복귀 .-> E
```

- 단일 인스턴스(Mutex)로 이중 실행 차단(TD-007).
- 실패 원인 구분: DEK 언래핑 실패=비번 오류 / 본문 태그 실패=파일 손상(design 5.3).

## 2. 최초 설정 마법사 (S2)

```mermaid
flowchart TD
    A[Step1 마스터 비밀번호] --> A1{12자 이상 · 흔한 비번 아님?}
    A1 -- 아니오 --> A
    A1 -- 예 --> B[Step2 복구 키 발급]
    B --> B1{"안전 보관 체크?"}
    B1 -- 아니오 --> B
    B1 -- 예 --> C[Step3 OTP 등록: QR 표시]
    C --> C1[폰으로 스캔 → 6자리 입력]
    C1 --> C2{코드 검증?}
    C2 -- 실패 --> C1
    C2 -- 성공 --> D[볼트 생성: DEK를 KEK·복구키로 이중 래핑]
    D --> E[메인 화면 S3]
```

- 강도 규칙: 길이 중심(최소 12자) + 흔한 비번 차단(TD-009).
- 복구 키 무조건 발급 + 보관 확인 체크(TD-010).

## 3. 비밀번호 열람 (OTP 게이트 + 지연 복호화)

```mermaid
flowchart TD
    A["상세에서 '보기' 클릭"] --> B[OTP 입력창 S5]
    B --> C{"TOTP 검증 (±30초)"}
    C -- 실패 --> B
    C -- 성공 --> D[해당 항목 비밀번호 복호화 · 표시]
    D --> E{복사?}
    E -- 예 --> F[클립보드 복사 → 20초 후 자동 삭제]
    D -. 일정 시간 후 .-> G[다시 마스킹]
```

- OTP는 암호학적 잠금이 아닌 열람 재확인 게이트(TD-004).
- 평소엔 잠가 두고 통과 순간에만 복호화(지연 복호화, design 5.5).

## 4. 계정 추가 / 편집 저장

```mermaid
flowchart TD
    A[계정 추가/편집 저장] --> B{비밀번호가 바뀌었나?}
    B -- 예 --> C[이전 값 → passwordHistory 적재]
    C --> C1[lastChangedAt 갱신 · 이력 상한 관리]
    B -- 아니오 --> D[updatedAt만 갱신]
    C1 --> E[민감값 DEK로 항목 암호화]
    D --> E
    E --> F[볼트 JSON 직렬화]
    F --> G[원자적 쓰기: tmp 작성 → bak 백업 → rename 교체]
    G --> H[메인 갱신]
```

- 비밀번호 변경 시에만 이력 적재(design 7.2).
- 원자적 쓰기로 저장 중 크래시에도 기존 파일 보존(TD-001, design 5.3).

## 5. 마스터 비밀번호 복구 (복구 키)

```mermaid
flowchart TD
    A["잠금 화면: 비밀번호를 잊으셨나요?"] --> B[복구 키 입력 S8]
    B --> C{Wrapped DEK recovery 언래핑}
    C -- 실패 --> B
    C -- 성공 --> D[새 마스터 비밀번호 설정]
    D --> D1{강도 규칙 통과?}
    D1 -- 아니오 --> D
    D1 -- 예 --> E[새 KEK로 DEK 재래핑 · 저장]
    E --> F[메인 화면]
```

- 복구 키로 DEK를 풀어 새 비번 설정. 서버·이메일 불필요(TD-010).
- 마스터 비번과 복구 키를 둘 다 잃으면 복구 불가.

## 6. 마스터 비밀번호 변경(rekey) · KDF 자동 상향

```mermaid
flowchart TD
    A[설정: 마스터 비번 변경] --> B[현재 비번 확인]
    B --> C{일치?}
    C -- 아니오 --> B
    C -- 예 --> D[새 비번 → 새 KEK 파생]
    D --> E[DEK를 새 KEK로 재래핑]
    E --> F[원자적 저장]

    G[로그인 시 KDF 파라미터 점검] --> H{권장치보다 낮음?}
    H -- 예 --> I[새 파라미터로 KEK 재파생 → DEK 재래핑 저장]
    H -- 아니오 --> J[변경 없음]
```

- 데이터 본문은 재암호화하지 않고 DEK 재래핑만(2단 키, TD-006).
- 마스터 키/복구 키가 각각 DEK를 감싸므로, 비번 변경 시 마스터 쪽 래핑만 갱신.

## 7. 슬랙 알림 (옵트인 · 비동기 · 베스트에포트)

```mermaid
flowchart TD
    A[이벤트 발생: 잠금해제 / 로그인 실패 / 비번 변경] --> N{전역 오프라인 스위치 차단?}
    N -- 예(기본) --> Z[아무 것도 안 함]
    N -- 아니오(해제됨) --> B{슬랙 알림 ON?}
    B -- 아니오 --> Z
    B -- 예 --> C{해당 이벤트 토글 ON?}
    C -- 아니오 --> Z
    C -- 예 --> D[템플릿에 허용 변수만 치환해 문구 구성]
    D --> E[["백그라운드 전송 (앱 동작과 분리)"]]
    E --> F{Webhook 전송 성공?}
    F -- 성공 --> G[완료]
    F -- 실패 --> H[로컬 로그만 기록 · 1회 재시도]
    A --> M[[앱 본연 동작: 잠금해제·저장은 알림과 무관하게 즉시 진행]]
```

- **전역 오프라인 스위치**가 최상위 게이트 — 차단(기본)이면 어떤 아웃바운드도 없음(TD-013).
- 알림은 **앱 동작을 절대 막지 않는다**(비동기·베스트에포트, TD-012).
- 문구는 **허용 변수 템플릿**으로 구성(secret 변수 미제공, TD-014). 사이트명은 기본 미포함.
