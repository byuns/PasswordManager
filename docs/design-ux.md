# 디자인 · UX 리모델링

기능 완료(M1~M5 + 백업/복원) 후, [[feedback-ui-polish-last]] 원칙에 따라 외형을 일괄 정비한다.
근거 결정은 `tradeoffs.md`(TD-023)에, 기능 설계는 `design.md`에 있다.

## 1. 방향

- **범위**: 네비게이션까지 재설계 (사이드바 도입) + 카드 리스트 + 디자인 토큰 일관화.
- **기반**: WPF-UI(Fluent, Dark). 기존 클래식 `ListView`/`GridView`가 테마를 안 따라 흰 배경으로
  렌더되던 문제(다크/화이트 혼재)를 근본 해결한다.
- **강조색(accent)**: **인디고 `#6366F1`** (현대·차분·세련). 시스템 기본 시안을 대체.

## 2. 셸 구조 — 두 모드

셸(`ShellViewModel`)은 상태에 따라 두 가지 레이아웃을 가진다.

| 모드 | 화면 | 사이드바 |
|---|---|---|
| **잠금(Locked)** | 새 볼트 생성 · 로그인 · 복구 | ❌ 없음. 중앙 정렬 카드, 풀스크린(첫인상) |
| **열림(Open)** | 계정 · 설정 · 메뉴얼 · 정보 | ✅ 왼쪽 사이드바 레일 |

집중 작업(계정 편집 · OTP 게이트 등 하위 흐름)에서는 `Section`이 `null`이 되어 레일을 숨긴다.

## 3. 열림 모드 — 사이드바 레일

`ui:NavigationView`는 쓰지 않는다. 폭 150의 `Border` 안에 `SidebarNavButtonStyle`을 입힌
`ui:Button` 4개를 쌓은 **커스텀 레일**이다(테마·강조 표현을 직접 통제하기 위함).

```
┌──────────┐ ┌──────────────────────────────────┐
│┃▓🗝 계정  │ │ 검색 [.................]      (＋)│  ← ┃▓ = 현재 섹션 강조
│  ⚙ 설정  │ │ ┌──────────────────────────────┐ │
│  📖 메뉴얼│ │ │ (S)  Steam                    │ │
│  ℹ 정보  │ │ │        메인  myid     [🔒인증] │ │
└──────────┘ │ └──────────────────────────────┘ │
             └──────────────────────────────────┘
```

- **🗝 계정**: 검색 + `＋`(원형 Primary) + 태그 칩 바 + **사이트별 그룹 카드 리스트**.
- **⚙ 설정**: 상단 툴바에 몰려 있던 보조 동작을 이전 —
  OTP 등록/재설정 · 마스터 비밀번호 변경 · 복구 키 재발급 · 자동잠금 시간 ·
  클립보드 삭제 시간 · 백업/복원 · 알림(네트워크 스위치 + 슬랙).
- **📖 메뉴얼**: 사용 안내. **주제별 섹션 카드**(시작하기 · 매일 쓰기 · 보안·복구) + **단축키 카드**.
  문구는 `ManualViewModel`이 데이터(`Sections`·`Shortcuts`)로 들고, View는 템플릿만 갖는다 —
  항목마다 같은 `Grid`를 복붙하던 구조를 걷어내 한 줄 추가로 항목을 늘릴 수 있다.
  아이콘은 문자열 이름(`"Key24"`)으로 지정하고 `SymbolNameConverter`가 `SymbolRegular`로 바꿔,
  ViewModel이 WPF-UI에 의존하지 않게 한다.
- **ℹ 정보**: 앱 버전 · 볼트 파일 위치(design 7.9 "정보" 섹션).
- **🔒 잠금**: 레일이 아니라 **상단 타이틀바 최좌측** 아이콘 버튼(`[잠금][제목]` 순).
  레일이 숨는 하위 흐름에서는 잠금도 함께 숨는다.

### 3.1 현재 섹션 강조

어느 메뉴를 보고 있는지 한눈에 알 수 있도록, 선택된 항목에만 세 가지를 겹쳐 준다.

| 요소 | 값 |
|---|---|
| 좌측 강조 바 | 강조색(인디고) 3 × 16, 반경 1.5. 항목 `Padding` 바깥 맨 왼쪽 |
| 배경 | `CardBackgroundFillColorSecondaryBrush` (아주 옅음) |
| 글자·아이콘 | `TextFillColorSecondary` → `TextFillColorPrimary` |

- 비선택 항목은 평소 보조 텍스트 색, 호버/포커스 시 기본 텍스트 색, 눌림 시 강조색(기존 유지).
- 배선: `ShellViewModel.Section` → `SectionActiveConverter`(value=현재 섹션, parameter=항목 섹션명)
  → 버튼 `Tag`(bool) → `SidebarNavButtonStyle`의 `DataTrigger`.
  `Tag`는 `object` 타입이라 트리거 값을 `sys:Boolean`으로 **명시**해야 한다
  (`Value="True"`로 두면 문자열과 비교돼 절대 안 걸린다).

> 상단에 버튼 7개가 난립하던 문제를 사이드바로 분산해 해소한다.

## 4. 카드 리스트 (계정)

- **사이트 하나 = 카드 하나**(계정 하나가 아님). 카드 머리에 **이니셜 아바타 + 사이트명**,
  그 아래 그 사이트의 계정 행들을 쌓는다.
- 계정 행: **라벨(굵게)** · **아이디(보조색)** · 태그 칩 · 우측 액션.
- 액션은 **인증 게이트**를 거친다(TD-032) — 처음엔 자물쇠 '인증' 버튼만,
  OTP 통과 후 **보기 · 편집 · 삭제**가 나타난다.
- 비밀번호·이력·**마지막 변경일**은 목록에 노출하지 않는다
  (열람은 OTP 게이트, design 5.4·TD-004 유지).
- 호버 시 강조색 테두리·은은한 배경 변화(`CardBorderStyle`).

### 4.1 즐겨찾기와 정렬 (TD-040)

- **별 버튼**은 계정 행 맨 왼쪽(아이디 앞)에 **항상** 보인다. 꺼짐은 회색 빈 별, 켜짐은 강조색 채운 별.
  핀은 비밀 노출이 아니라 **OTP 인증 없이** 바로 토글된다.
- 핀한 계정은 목록 맨 위 **"즐겨찾기" 그룹**에 모인다. 즐겨찾기는 **바로가기**라
  **원래 사이트 그룹에도 그대로 남는다**(같은 계정이 두 곳에 보인다).
  - 그룹 머리에는 이니셜 아바타 대신 **별 배지** — 사이트가 아니기 때문.
  - 즐겨찾기 그룹의 행에만 **사이트명을 굵게 앞에 붙인다**(`Steam · main@…`). 그룹 헤더가
    사이트명을 알려주지 않으므로, 이게 없으면 어떤 서비스인지 알 수 없다.
  - 배선: 행 템플릿이 가장 가까운 `ItemsControl`(계정 목록)의 `DataContext.IsFavorites`를
    `DataTrigger`로 보고 사이트명 노출을 켠다.
- **정렬 드롭다운**은 검색창과 ＋ 버튼 사이. 이름순 / 최근 변경순 / 최근 사용순이며 볼트에 저장된다.
  즐겨찾기 그룹은 정렬과 무관하게 항상 맨 위에 남는다.

### 4.2 휴지통 (TD-041)

- 진입점은 **설정 > 백업·데이터**의 "휴지통" 카드(보관 개수를 함께 표시). 사이드바는 늘리지 않는다.
- 휴지통은 **하위 흐름**이라 사이드바를 숨기고, 머리말 왼쪽 `←` 버튼으로 설정에 돌아간다.
- 각 행은 흐린 이니셜 아바타 + 사이트명/아이디 + **"N일 뒤 완전 삭제"** + [복원] [영구 삭제].
- 비어 있으면 아이콘과 안내 문구만 가운데 놓는다.

## 5. 키보드 단축키 (TD-039)

마우스 없이 매일 쓰는 동선이 끝나도록 계정 화면에 단축키를 둔다.

| 키 | 동작 |
|---|---|
| `Ctrl+F` | 검색창 포커스 (기존 검색어는 전체 선택돼 바로 덮어쓸 수 있음) |
| `Ctrl+N` | 새 계정 |
| `Ctrl+L` | 즉시 잠금 |
| `Ctrl+B` | 선택 항목 **아이디** 복사 |
| `Esc` | 검색어 + 태그 필터 한 번에 해제 |
| `↑` / `↓` | 선택 이동 (양끝에서 멈추고 순환하지 않음) |
| `Enter` | 선택 항목 인증 (OTP 게이트) |

- **비밀번호 복사 단축키는 없다.** 열람은 OTP 게이트를 거쳐야 하므로(TD-004·TD-032),
  키 한 번에 복사되면 게이트가 무의미해진다. 아이디만 연다(TD-027).
- 배선은 `MainView`의 `InputBindings` → `MainViewModel` 커맨드 직결.
  `Ctrl+F`만 포커스 이동이라 `ApplicationCommands.Find` → 코드비하인드가 처리한다.
- `InputBindings`는 **포커스가 이 화면 안에 있어야** 발동하므로, `Loaded`에서 검색창에 포커스를 준다.
- 확인 오버레이가 떠 있을 땐 포커스가 트랩되어(2장) 이 단축키들은 발동하지 않는다.
- **메뉴얼 화면의 단축키 카드**에 같은 목록을 키칩 배지로 싣는다. 두 곳이 어긋나지 않도록
  `ManualViewModelTests`가 단축키 7개와 각 키 조합을 검증한다.

### 5.1 목록 선택 강조

↑/↓·Enter·Ctrl+B의 대상이 되는 "현재 행"을 **옅은 배경**으로만 표시한다.

| 요소 | 값 |
|---|---|
| 배경 | `CardBackgroundFillColorSecondaryBrush` (아주 옅음), 반경 6 |

- **좌측 강조 바는 두지 않는다** — 3.1절 사이드바(항목 4개, 넉넉한 간격)와 달리 계정 행은
  카드 안에 촘촘히 쌓여 있어, 세로 바가 붙으면 산만해진다. 배경만으로 충분히 읽힌다.

- 행 아무 곳이나 클릭해도 선택된다(키보드 선택과 같은 상태를 공유).
- 배선: `MainViewModel.SelectedEntry`·`SelectionInFavorites` + 행의 항목·그룹 →
  `EntrySelectedConverter`(MultiBinding 4값) → `Visibility`.
  - 핀한 계정은 즐겨찾기·사이트 그룹에 **같은 인스턴스**로 두 번 나오므로, 항목만 비교하면 두 행이
    동시에 켜진다. **어느 그룹의 행인지까지 일치해야** 강조한다(TD-045).
  - 키보드 이동(↑↓)은 중복 없는 평면 목록 기준이라 **사이트 그룹 쪽**을 고른다. 끝에서 멈춰
    이동이 없었다면 현재 강조를 유지한다.
- **선택은 화면에 보이는 목록에만 머문다** — 검색·태그 필터나 삭제로 항목이 사라지면
  `Refresh()`가 선택을 함께 해제한다.

## 6. 디자인 토큰

- **여백 스케일**: 4 · 8 · 12 · 16 · 24 (px). **숫자 규약이지 리소스가 아니다** —
  실제 여백은 대부분 방향성(`Margin="0,0,0,8"`)이라 균일 `Thickness` 토큰이 안 맞아,
  화면 바깥 여백용 `ThicknessL`(16) 하나만 리소스로 둔다.
- **타이포**: WPF-UI `TextBlock` FontTypography (Title / Subtitle / Body / Caption).
- **카드**: 모서리 반경 8, 은은한 테두리(`CardBackground`/`ControlStroke`), 호버 강조.
- **색**: 배경/표면/텍스트는 WPF-UI Dark 토큰(`ApplicationBackground`, `CardBackground`,
  `TextFillColorPrimary/Secondary`)에 의존. 강조만 인디고로 오버라이드.
